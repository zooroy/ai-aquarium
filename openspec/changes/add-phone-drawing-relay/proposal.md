# Proposal

## Why

現在只能在桌電的魚缸上畫魚。使用者希望拿 iPhone 也能畫魚，畫好後送進桌電的魚缸；手機本身不需要顯示 3D 魚缸。手機和桌電可能不在同一個網路，所以要把魚缸部署到網路上，用一個小後端轉交手機畫的魚。

## What Changes

- **依裝置分流**：觸控為主、螢幕短邊小的裝置（手機）只顯示全螢幕畫圖頁，不載入 3D 魚缸、手部追蹤，也不要求相機。iPad、桌電、筆電照常顯示魚缸。網址參數可以強制指定模式，方便測試。
- **手機畫圖頁**：沿用現有的畫布、色票、筆刷、橡皮擦、復原、清除，版面改成適合手機直式螢幕。按「送進魚缸」後把魚上傳；成功顯示完成畫面，可以再畫一隻；失敗時保留畫的內容，可以重試。
- **魚缸配對**：每個桌電魚缸有一個隨機、難以猜到的房間代碼，存在這台桌電上，重新整理後不變。魚缸選單新增「用手機畫」按鈕，打開後顯示含房間代碼網址的 QR code。手機掃描後打開綁定這個房間的畫圖頁，魚只會進這個魚缸。
- **接收手機的魚**：桌電魚缸定期向後端查詢這個房間有沒有新魚。收到後跟本機畫的魚一樣處理：從中央游出、存進這台桌電的 IndexedDB、計入 20 隻上限、可以在「我的魚」刪除。存好之後通知後端刪除。已滿 20 隻時，魚留在後端等待，並提示使用者先刪除一隻。
- **轉交後端**：使用 Supabase，免費方案不需要綁卡。圖片暫存在 Supabase 的資料表，前端只能透過幾個資料庫函式存取，看不到其他房間的魚。後端只做轉交：檢查圖片格式與大小、限制每個房間的待領數量，魚送達後刪除，沒人領的魚一天後自動清掉。
- **網頁部署**：網頁放在 GitHub Pages，即公開 repo `zooroy/ai-aquarium`，由 GitHub Actions 建置後發布。網站在子路徑 `/ai-aquarium/` 下，所以靜態資源的路徑要跟著調整。
- **後端選擇的變更**：原本規劃用 Cloudflare（Workers + R2），但啟用 R2 需要綁定付款方式，使用者不想綁卡，所以改成 GitHub Pages + Supabase。

## Capabilities

### New Capabilities

- `phone-drawing`: 依裝置分流，以及手機上的全螢幕畫圖頁與送出流程。
- `tank-pairing`: 桌電魚缸的房間代碼、QR code 面板，以及接收手機送來的魚。
- `fish-relay`: 後端轉交 API 的行為，包括驗證、數量限制、送達後刪除與過期清除。

### Modified Capabilities

- `aquarium-scene`: 「全螢幕魚缸畫面」改為只在非手機裝置上顯示；手機改顯示畫圖頁。

## Impact

- **前端**：
  - `src/main.ts` 先判斷裝置，再動態載入魚缸或畫圖頁，讓手機不必下載 Three.js 和 MediaPipe。
  - 新增 `src/phone/`（手機畫圖頁）和 `src/relay/`（轉交 API 客戶端、房間代碼、接收輪詢）。
  - 畫圖面板的畫布與工具抽成可重用的元件，給桌電面板和手機頁共用。
  - `fish-menu`、`custom-fish-feature` 加上「用手機畫」和接收流程。
- **後端**：新增 `supabase/migrations/` 的 SQL，包括資料表、函式、權限與排程清除；新增 `.github/workflows/` 的 Pages 部署流程。
- **依賴**：
  - 執行時：`uqr`，用來產生 QR code。前端直接用 `fetch` 呼叫 Supabase 的 REST API，不安裝 `supabase-js`。
  - 開發時：`@electric-sql/pglite`，在 node 測試裡執行真正的 Postgres 來測 SQL 函式。
  - 這些由 Claude 安裝，因為 Codex 沙盒沒有網路。
- **外部服務**：
  - 使用者需要一個 Supabase 帳號和一個免費專案。
  - 免費專案一週沒有任何請求會自動暫停，要到後台手動恢復。
  - 這個 repo 會在使用者的 GitHub 帳號 zooroy 下公開。
- **不在範圍內**：
  - 手模型的 CC BY 作者標示：已提醒使用者，使用者沒有要求加上。
  - 帳號登入。
  - 雲端永久保存。
  - 撤銷或更換房間代碼。
  - 公共共用魚缸。
  - 內容審查。
